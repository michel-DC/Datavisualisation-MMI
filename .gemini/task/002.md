# Tâche — Section « Évolution des précipitations en Guadeloupe »

## Contexte général

Tu interviens sur un projet de datavisualisation réalisé dans le cadre de la SAE 303 (BUT MMI).

Toutes les règles de développement, de structuration et d’écriture du code sont définies dans le fichier `AGENTS.md`.  
Ces règles doivent être respectées strictement, sans exception.

Stack utilisée :

- PHP
- Tailwind CSS
- Chart.js
- GSAP
- Lucide Icons

Le site est une **single page strictement non scrollable** (aucun scroll vertical ni horizontal).

La section « Températures » est déjà terminée et sert de **référence structurelle et qualitative**, notamment le fichier :

- `@/sections/temperatures.php`

---

## Objectif de la tâche

Créer la **section dédiée à l’évolution des précipitations en Guadeloupe**, avec un layout différent de la section températures, tout en conservant une cohérence globale de design, d’UX et de structure.

Cette tâche concerne uniquement **cette section**.  
Aucune autre section ne doit être modifiée.

---

## Données (contrainte essentielle)

Pour cette étape du projet :

- **Aucune API ne doit être utilisée**
- **Aucune donnée réelle n’est requise**
- Les données doivent être :
  - **Fictives**
  - **Définies directement dans le code**
  - Suffisamment nombreuses pour couvrir la période **1950 à 2023**
- Les valeurs doivent être plausibles et cohérentes avec des données de précipitations (variabilité interannuelle, pics exceptionnels)

Toute source externe ou appel réseau est strictement interdit.

---

## Emplacement et structure

- La section doit être créée dans :
  - `/sections/precipitations.php`
- Les graphiques doivent utiliser des scripts dédiés situés dans :
  - `/script/`
- La section doit être compatible avec le système d’affichage / masquage existant
- La section doit occuper **100 % du viewport**, sans scroll

---

## Structure générale de la section

### 1. Modal d’introduction (au chargement de la section)

- À l’affichage initial de la section, un **modal informatif** doit apparaître
- Ce modal s’inspire du comportement et du style du modal présent dans `@/sections/temperatures.php`

Contenu du modal :

- Texte pédagogique expliquant :
  - L’importance des précipitations en Guadeloupe
  - Les risques liés à l’augmentation des cumuls et aux épisodes extrêmes
- Bouton ou interaction permettant de fermer le modal

Contraintes :

- Apparition animée avec GSAP
- Modal clair, lisible, non intrusif
- Fermeture fluide

---

### 2. Titre de section

- Une fois le modal fermé, la section principale est visible
- Le **titre de la section** doit être :
  - Positionné **en haut**
  - **Centré horizontalement**
  - Typographiquement fort et lisible

Exemple de sens attendu (le wording exact est libre) :

- « Évolution des précipitations en Guadeloupe »

---

### 3. Graphique principal (centre de la page)

Contient :

- Un graphique Chart.js montrant :
  - Le **cumul annuel des hauteurs de précipitations**
  - Unité : **millimètres**
- Période couverte :
  - **1950 à 2023**

Contraintes graphiques :

- Un seul graphique principal
- Représentation claire de l’évolution annuelle
- Axes lisibles et correctement nommés
- Animation d’apparition maîtrisée (GSAP)
- Aucune surcharge visuelle

---

### 4. Légende (bas de page)

- La légende du graphique principal est placée :
  - **En bas de la section**
- Elle doit :
  - Être lisible
  - Expliquer clairement ce que représente le graphique
  - Utiliser une typographie plus discrète que le titre

---

### 5. Texte cliquable et modal secondaire

Dans la section principale, ajouter :

- Un **texte cliquable** (lien ou bouton textuel)
- Ce texte ouvre un **second modal**

#### Contenu du modal secondaire

Le modal affiche :

- Un graphique Chart.js représentant :
  - L’évolution du **cumul maximal de précipitations tombées en 24h**
  - Pour chaque année, seule la **valeur maximale annuelle** est conservée
- Unité : **millimètres**
- Période : **1950 à 2023**

Contraintes :

- Graphique distinct du graphique principal
- Données fictives définies dans le code
- Animation GSAP à l’ouverture et à la fermeture
- Modal clair, centré, lisible
- Une seule instance visible à la fois

---

## Contraintes UI / UX

- Style **strictement minimaliste**
- Aucune couleur flashy
- Aucun gradient
- Palette sobre et cohérente avec la section températures
- Typographie large et hiérarchisée
- Espaces maîtrisés
- Interface de type dashboard

L’ensemble doit s’intégrer naturellement avec les autres sections du site.

---

## Contraintes techniques

- Utiliser Tailwind CSS pour le layout et le style
- Utiliser Chart.js uniquement pour les graphiques
- Utiliser GSAP pour :
  - L’apparition des modals
  - Les transitions visuelles
- Code :
  - Propre
  - Structuré
  - Lisible
  - **Sans commentaires**
- Une responsabilité par fichier
- Aucun code inutile ou expérimental

3. Les scripts nécessaires à la gestion des modals
4. Les animations GSAP associées

L’ensemble doit être immédiatement exploitable et cohérent avec la section températures existante.
