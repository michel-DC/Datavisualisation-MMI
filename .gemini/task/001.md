# Tâche — Section « Évolution des températures en Guadeloupe »

## Contexte général

Tu interviens sur un projet de datavisualisation réalisé dans le cadre de la SAE 303 (BUT MMI).

Toutes les règles de développement, de structuration et d’écriture du code sont définies dans le fichier `AGENTS.md`.  
Ces règles doivent être respectées strictement, sans exception.

Stack utilisée :

- PHP
- Tailwind CSS
- Chart.js
- GSAP
- Lucide Icons

Le site est une **single page strictement non scrollable** (aucun scroll vertical ni horizontal).

---

## Objectif de la tâche

Créer **la section dédiée à l’évolution des températures en Guadeloupe**, avec une **intégration complexe**, à la fois visuelle, interactive et rigoureusement structurée.

Cette tâche concerne uniquement **cette section**.  
Aucune autre section du site ne doit être modifiée ou créée.

---

## Données (contrainte essentielle)

Pour cette étape du projet :

- **Aucune API ne doit être utilisée**
- **Aucune donnée réelle n’est requise**
- Les données doivent être :
  - **Fictives**
  - **Définies directement dans le code**
  - Suffisamment nombreuses pour couvrir la période **1950 à 2023**
- Les valeurs doivent être cohérentes et plausibles (évolution progressive, tendances crédibles)
- Les données doivent permettre :
  - L’affichage des températures minimales et maximales
  - La distinction par zones pour la carte

Toute tentative d’appel à une API ou à une source externe est interdite.

---

## Emplacement et structure

- La section doit être créée dans le dossier :
  - `/sections/`
- Le graphique doit utiliser un script dédié situé dans :
  - `/script/`
- La section doit être compatible avec le système d’affichage / masquage déjà prévu via la sidebar
- La section doit occuper **100 % du viewport**, sans scroll

---

## Découpage de l’écran

L’écran est divisé en **trois zones verticales distinctes** :

### 1. Zone gauche — Contenu éditorial

Contient :

- Des textes explicatifs sur l’évolution des températures en Guadeloupe
- Un message de mise en garde sur la hausse des températures
- La légende du graphique central

Contraintes :

- Texte clair, synthétique, hiérarchisé
- Typographie large et lisible
- Aucun contenu décoratif inutile
- Alignements et espacements précis

---

### 2. Zone centrale — Graphique principal

Contient :

- Un graphique Chart.js représentant :
  - L’évolution des températures **maximales**
  - L’évolution des températures **minimales**
- Période couverte : **1950 à 2023**
- Données globales pour la Guadeloupe (pas par zone)

Contraintes graphiques :

- Deux courbes uniquement (min / max)
- Graphique lisible et épuré
- Pas de surcharge visuelle
- Axes, légendes et labels clairs
- Animation d’apparition maîtrisée (GSAP)

---

### 3. Zone droite — Carte de la Guadeloupe

Contient :

- Une **carte de la Guadeloupe dessinée en SVG**
- La carte est découpée en **zones distinctes** (régions ou secteurs)

Interactions :

- Effet visuel au hover sur chaque zone
- Au clic sur une zone :
  - Affichage d’un **menu flottant**
  - Le menu affiche :
    - Nom de la zone
    - Température maximale en 1950
    - Température maximale en 2023
    - Température minimale en 1950
    - Température minimale en 2023

Contraintes :

- Le menu flottant apparaît avec une animation GSAP
- Une seule zone active à la fois
- Le menu se met à jour dynamiquement selon la zone cliquée

---

## Contraintes UI / UX

- Style **strictement minimaliste**
- Aucune couleur flashy
- Aucun gradient
- Palette sobre et cohérente avec le reste du site
- Typographie large et élégante
- Interface de type dashboard
- Interactions fluides, naturelles et justifiées

L’objectif est une **harmonie visuelle parfaite** et une expérience utilisateur claire et fluide.

---

## Contraintes techniques

- Utiliser Tailwind CSS pour le layout et le style
- Utiliser Chart.js uniquement pour le graphique central
- Utiliser GSAP pour :
  - L’apparition de la section
  - L’animation du graphique
  - L’affichage du menu flottant
- La carte doit être un SVG natif, intégré proprement dans le DOM
- Le code doit être :
  - Propre
  - Structuré
  - Lisible
  - Sans commentaires
- Une responsabilité par fichier
- Aucun code expérimental ou inutile
